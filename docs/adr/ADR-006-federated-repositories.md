# ADR-006: 联邦式软件源（Federated Repositories）

- 状态：Accepted
- 日期：2026-07-30
- 相关：ADR-007, ADR-008, ADR-010；`docs/TRP-v1.md`

## 背景

第一轮产品（后公开命名为 Useful；技术身份仍保留 useful 兼容名）是本地工具平台，工具源模型简单。第二轮要扩展为「开源客户端 + 开放协议 +
可自托管后端 + 官方订阅源」。需要一个不把官方源写死、允许任意人自托管的联邦模型。

## 决策

采用 **TRP v1**（Useful 联邦软件源协议；兼容历史名称 Useful Repository Protocol）作为客户端与软件源之间的开放协议：

- 客户端可添加/删除/禁用/更换任意合法源；无需中心账户即可使用免费与自定义源。
- 每个源独立：独立信任根、账户、权限、订阅、下载策略。源之间不共享 OAuth Token。
- 官方源仅为默认预置源，协议层不赋予不可替代的特殊权力（官方性判定见 ADR-007/008）。
- 协议工件公开且可测试：JSON Schema + OpenAPI 3.1 + 测试向量，位于 `packages/protocol`。
- 自定义源是正式产品能力，不藏在开发者模式；文案用「更换服务提供商」「自托管」，
  不描述为破解/绕过。

## 后果

- 客户端需要多源数据模型、按源隔离的缓存与账户（Phase 6B）。
- 需要静态源生成器（Phase 6C）与动态 Go 后端（Phase 7）两种参考实现。
- 协议一致性由 `pnpm --filter @useful/protocol test` 守护，防止回归。
